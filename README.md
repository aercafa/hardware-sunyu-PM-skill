# Hardware Product Lifecycle Skill

一个面向**实体硬件与软硬件一体产品**的 Codex 全周期产品开发 Skill。

它既可以在新项目开始时按阶段引导，也可以读取进行中的项目，判断当前阶段、有效基线、关键缺口、未冻结决策和版本治理问题。

## 主要能力

- 从机会识别到项目结项的九阶段生命周期
- 概念探索级与标准产品研发级两种流程强度
- 每次调用先对齐项目状态和本次决策
- 产品定义、故事板、体验流程、框架图和产品图谱引导
- 工程模组与代表产品协同设计
- 从体验目标到可测试工程指标的两阶段量化
- 阶段门、阻断项、风险接受和决策记录
- 样机、试产、产品手册和内外白皮书编制
- 文件分类、版本、验证状态、基线和增量迭代治理
- 项目巡检、结项复盘和资产沉淀

## 安全原则

Skill 可以自动读取、比较和诊断文件，但下列操作必须先汇报并获得明确批准：

- 删除
- 移动
- 重命名
- 归档
- 合并目录
- 改变文件夹结构

“整理文件”或“清理旧版”不构成执行授权。批准只适用于当次列明的操作。

## 生命周期

1. 机会识别
2. 前期研究
3. 产品定义
4. 产品设计
5. 工程开发
6. 样机验证
7. 试产验证
8. 产品手册与白皮书
9. 项目总结与资产沉淀

产品设计阶段包含两条协同主线：

- **工程模组**：产品族共用的内部机芯、尺寸骨架、接口和兼容规则
- **标准产品**：由模组、配置、安装方式、交互和外观组成的具体产品

先选择代表性标准产品约束模组，协同设计，模组接口优先冻结，再扩展产品族。

## 使用方式

调用：

```text
$hardware-product-lifecycle
```

示例：

```text
使用 $hardware-product-lifecycle 读取当前项目，判断所处阶段、关键缺口和本次需要确认的决策。
```

每次调用会先：

1. 检查项目总控、目录、当前基线、最近变化和未决事项
2. 判断项目等级与生命周期阶段
3. 说明已经成立、仍是假设和缺少证据的内容
4. 提出本次需要确认的 1-3 个关键决策
5. 用户确认后再执行当前工作
6. 结束时更新进度、文件状态、决策和下一步入口

## 关键规则

### 文件状态

- 草案
- 当前有效
- 已归档
- 待清理

### 验证状态

- 未验证
- 已评审
- 已测试

“最新版”不等于“已验证”，“已验证”也不一定是“当前有效”。

### 证据

- 优先使用法规、标准、原厂资料、直接观察、正式测试等一手证据
- 区分事实、推断、建议、假设和决策
- 供应商型号、价格、接口和生命周期在采购前重新核验
- 未验证结论不能进入工程冻结基线

### 工程量化

- 产品定义阶段确定目标范围、使用边界和体验要求
- 工程开发前转换为参数、容差、测试方法和验收阈值
- “快”“稳定”“工业级”“易维护”不能直接作为冻结要求

## 安装

将仓库克隆到 Codex Skills 目录，并将本地文件夹命名为 `hardware-product-lifecycle`：

```bash
git clone https://github.com/aercafa/hardware-sunyu-PM-skill.git \
  ~/.codex/skills/hardware-product-lifecycle
```

重新加载 Codex 后，可使用 `$hardware-product-lifecycle` 调用。

## 来源

本 Skill 总结自一项博物馆交互信息终端产品研发实践，吸收了其中有效的方法，也针对实践暴露的问题加入了主动巡检：

- 发散充分但冻结偏晚
- 框架完整但真实验证不足
- 工程指标量化进入较晚
- 需求、设计和测试缺乏追踪
- 文件版本多、当前基线不清
- 产品定义与工程、供应链、商业闭环衔接不足

Skill 将这些经验抽象为通用软硬件产品开发规则，不限定于博物馆或展陈行业。
